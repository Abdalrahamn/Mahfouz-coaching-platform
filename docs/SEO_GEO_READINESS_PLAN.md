# خطة جاهزية SEO وGEO — محفوظ

تاريخ الخطة: ١٨ نوفمبر ٢٠٢٦ — Africa/Cairo.
النطاق الحالي: https://mahfouz-coaching.pages.dev/

هذه قائمة تنفيذ مشتركة طلبها المالك للوصول إلى جاهزية عالية جدًا، وليست إعلانًا باكتمال مراجعة شاملة أو ضمانًا للمركز الأول. لا نضع نسبة جاهزية تقديرية بلا دليل. البنود أدناه تشمل أشياء موجودة وتحتاج تحققًا أوسع، لا أشياء ثبت غيابها كلها.

اقرأ أولًا [الفحص المؤرخ والأدلة](SEARCH_VISIBILITY_AUDIT_2026-11-18.md). تظل [قائمة المتابعة التاريخية](SEARCH_VISIBILITY_TODO.md) سجل نتائج الفحوص السابقة. هذه الخطة هي ترتيب العمل القادم، ولا تعيد فتح ما نجح لمجرد تكراره.

## الحالة التي نبدأ منها

- [x] عناوين ووصف باللغتين، canonical وhreflang، robots وsitemap وبيانات Person/Service موجودة في الصفحات الرئيسية المنشورة التي فحصناها.
- [x] دخول جديد عربي، مع احترام اللغة المحفوظة. بقاء نسختين لا يمنع الفهرسة بحد ذاته.
- [x] فحص Google المباشر للخريطة يوم ١٨ نوفمبر نجح؛ لا يوجد حظر وصول مثبت بسبب Cloudflare في هذه العينة.
- [x] كلمات المالك موزعة في المصدر بصورة طبيعية؛ فحوص الكود والبناء وخمس اختبارات وحدة واختبار اللغة نجحت، وفُحصت الصفحات الرئيسية ودليل الأسعار في اللغتين على عرضي 390 و1280.
- [ ] نشر تعديلات الكلمات الأخيرة: لم يحدث بعد. النسخة المحلية ليست النسخة العامة.
- [ ] فهرسة الصفحتين الرئيسيتين: آخر فحص يقول URL is unknown to Google.
- [ ] معالجة الخريطة المقدمة: آخر تقرير يقول Couldn't fetch رغم نجاح الفحص المباشر.
- [ ] فحص أداء شامل لكل المسارات، مراجعة المنافسين، تحقق كامل للبيانات المنظمة، وقياسات GEO المستقلة: ليست منجزة في الفحص السابق.

## المرحلة الأولى — نشر مضبوط وإزالة عوائق الاكتشاف

### R01 — نشر التعديلات المجهزة والتحقق من النسخة العامة

- [ ] مراجعة فرق المصدر الحالي، ثم نشره بالطريقة القائمة إلى Cloudflare Pages عند تنفيذ مرحلة النشر مع المالك.
- معيار الإغلاق: تسجيل commit وdeployment والوقت، وقراءة الكلمات الجديدة من HTML العام في `/ar` و`/en` ودليلي الأسعار، مع استمرار الأسعار والخصوصية والروابط الرسمية واللغتين كما هي.
- المسؤول: التنفيذ الفني. إجراء النشر نفسه لم يحدث في هذه الخطة. لا ننقل الاستضافة أو نشتري نطاقًا كحل افتراضي.

### R02 — حسم حالة sitemap في Google Search Console

- [ ] فتح تفاصيل خطأ الخريطة وآخر قراءة، ومقارنة تقرير المعالجة باختبار الجلب المباشر الناجح. إعادة تقديم واحدة عند الحاجة، ثم متابعة النتيجة؛ لا إرسال متكرر باعتباره تسريعًا.
- [ ] عند تكرر الفشل: توثيق الردود والرؤوس من Google Inspection وسجلات الطلبات المتاحة، وفحص DNS/TLS/CDN/WAF حسب الدليل؛ إحالة المشكلة للدعم إن بقي فشل المعالجة بلا خطأ قابل للإصلاح.
- معيار الإغلاق التشخيصي: سبب موثق وإصلاحه إن وُجد، أو تصعيد موثق يوضح ما ينتظر المزود. معيار النجاح الخارجي المنفصل: تقرير الخريطة Success/آخر قراءة وصفحات مكتشفة.
- نجاح Test Live URL وحده لا يغلق مشكلة تقرير المعالجة. لا نعطل حماية Cloudflare دون دليل.

### R03 — طلب فهرسة صفحات الخدمة المهمة ومتابعتها

- [ ] فحص `/ar` و`/en` و`/ar/online-coaching-prices` و`/en/online-coaching-prices`، وتسجيل canonical المحدد وحالة الزحف والفهرسة، وطلب الفهرسة عندما تسمح الحصة.
- معيار إنجاز الإجراء: حالة ووقت الطلب موثقان لكل URL، أو سبب رفض الحصة وموعد متابعة واضح. معيار النتيجة الخارجي: URL is on Google لكل صفحة مؤهلة؛ قبول الطلب لا يساوي الفهرسة.
- لا يلزم ظهور صفحات الشروط والخصوصية ككلمات تجارية، ولا فهرسة ملف XML كصفحة نتائج بحث.

### R04 — التحقق من Bing Webmaster Tools

- [ ] معرفة هل النطاق مسجل ومثبت بالفعل، ثم استكمال التحقق وتقديم الخريطة إن لم يكن كذلك، وفحص أهم URLs وأخطاء الزحف.
- معيار الإغلاق: إثبات الملكية وحالة تقديم/قراءة الخريطة وحالة صفحات الخدمة مسجلة. هذا مسار اكتشاف إضافي؛ ليس ضمان ترشيح في أي مساعد.
- إعداد الحساب أو أي وصول جديد يتبع صلاحيات المالك. لم نفحص حساب Bing حتى الآن.

## المرحلة الثانية — مراجعة تقنية كاملة لكل المسارات

### R05 — زحف داخلي شامل للنطاق المنشور

- [ ] فحص كل URL عام في الخريطة وكل رابط داخلي قابل للزحف، بما فيه الجذر والصفحات القانونية ودليل الأسعار وصور الموقع الأساسية.
- معيار الإغلاق: لا روابط داخلية مكسورة أو حلقات تحويل أو صفحات وهمية ترجع 200 بدل 404؛ المحتوى الأساسي متاح في HTML؛ لا صفحات خدمة معزولة؛ HTTP/HTTPS والشرطات ومسارات اللغة لها سلوك موثق وثابت.
- لا تولّد نسخ URLs متكررة من الفلاتر أو الباقات أو query parameters دون حاجة.

### R06 — مراجعة عناوين وcanonical واللغات لكل صفحة

- [ ] فحص title وdescription والعنوان الرئيسي وبنية العناوين وcanonical وروابط alternates المتبادلة على كل المسارات، وليس الرئيسية فقط.
- معيار الإغلاق: عنوان ووصف مناسب ومميز لكل نية بحث، canonical صحيح لكل لغة، وعدم إرسال العربية إلى canonical إنجليزي، واتساق المسارات في sitemap. ترتيب عناوين الصفحة منطقي بلا حشو كلمات.
- قرار اختياري موثق: هل نغير x-default من الإنجليزية للعربية لمطابقة جمهور البداية؟ ليس عائقًا مثبتًا، ولا نغير اختيار الزائر المحفوظ.

### R07 — التحقق من البيانات المنظمة ومطابقتها للمحتوى

- [ ] فحص JSON-LD بمحقق Schema.org، واستخدام Google Rich Results Test للأنواع التي يدعمها فقط؛ فحص Person/Service/WebPage والصورة والروابط الرسمية واللغة ومعرّفات الكيانات عبر النسختين.
- معيار الإغلاق: لا أخطاء تركيب/نوع، ولا بيانات تناقض الصفحة أو أسماء وشهادات وأرقام نتائج مختلقة. الأسعار إن أضيفت تستخدم بيانات business.ts نفسها. يوثق كل تحذير غير قابل للتطبيق بدل اعتباره فشلًا وهميًا.
- Schema صحيحة لا تضمن نتيجة غنية. لا نضيف FAQ أو تقييمات أو LocalBusiness وهمية لمطاردة شكل نتيجة.

### R08 — قياس السرعة وCore Web Vitals

- [ ] قياس الصفحتين الرئيسيتين ودليلي الأسعار على الموبايل والكمبيوتر، وحفظ تقرير PageSpeed/Lighthouse وتشخيص الصور والخطوط والـJavaScript والانزياح البصري.
- [ ] إصلاح المشاكل المثبتة، ثم إعادة القياس على الصفحات المتأثرة فقط.
- معيار الاستهداف الميداني: LCP ≤ 2.5 ثانية، INP ≤ 200 مللي ثانية، CLS ≤ 0.1 عند المئين 75 متى توفرت بيانات مستخدمين كافية. سجل بيانات الصفحة أو النطاق كما هي، ولا تعتبر غياب البيانات نجاحًا أو فشلًا.
- قياس المعمل مفيد للتشخيص ولا يثبت اجتياز INP الميداني. لا نجعل درجة Lighthouse وحدها شهادة SEO.

### R09 — مراجعة العرض والوصول والصور على المسارات المتأثرة

- [ ] استكمال فحص أحجام الموبايل والكمبيوتر واللغتين، لوحة المفاتيح والتركيز والتكبير والروابط وفتح الأسئلة، وسلامة alt للصور ذات المعنى والتحميل المرئي.
- معيار الإغلاق: محتوى الخدمة واضح وقابل للقراءة بلا تداخل أو خروج أفقي، لا أخطاء وصول حرجة في النطاق المفحوص، والصور الأساسية قابلة للجلب. لا تستخدم alt كقائمة كلمات بحث.
- أعد اختبارات موجودة مناسبة بعد تحديث توقعاتها القديمة عند الحاجة؛ لا تصف الفحص الجزئي بأنه مرور كامل للاختبارات التاريخية.

## المرحلة الثالثة — محتوى وهوية يمكن الوثوق بهما

### R10 — بحث الكلمات والمنافسين وربط النية بالصفحة

- [ ] بحث عينة نتائج مصر بالعربية والإنجليزية وتسجيل التاريخ والعبارة والصفحات المنافسة؛ استخدام بيانات Search Console عند ظهورها، وأي بيانات أحجام بحث متاحة مع تسمية مصدرها.
- معيار الإغلاق: كل مجموعة لها نية وصفحة هدف واضحة، مع فصل الاسم التجاري عن عبارات الخدمة والأسعار والمبتدئين. لا نختلق أحجام البحث أو نفترض منافسة منخفضة.
- الأولويات التي طلبها المالك: مدرب أونلاين في مصر، كابتن أونلاين في مصر، تدريب أونلاين في مصر، أونلاين كوتشينج، كابتن عبدالرحمن/عبد الرحمن محفوظ، وأسعار التدريب الأونلاين في مصر. لا نعمل صفحة متشابهة لكل تهجئة.

### R11 — محتوى يجيب عن أسئلة الاشتراك الفعلية

- [ ] تحسين الرئيسية والدليل أولًا حسب فجوات R10، ثم إعداد موضوعات منفصلة فقط عندما تضيف إجابة مختلفة ومفيدة: طريقة المتابعة، ما تشمل الباقة، الاختيار بين المتابعة اليومية والبرنامج المستقل، وتجهيز البداية للمبتدئ.
- معيار الإغلاق لكل صفحة: سؤال واضح وإجابة مباشرة وتفاصيل خدمة صحيحة، اسم الكاتب/المراجع حيث يلزم وتاريخ مراجعة حقيقي وروابط داخلية مناسبة، وتغطية اللغتين. لا تكرار آلي أو صفحات مدن أو «أفضل كوتش» كادعاء بلا دليل.
- المحتوى الصحي/التغذوي التخصصي يحتاج مصادر أولية ومراجعة شخص مؤهل بما يناسب موضوعه. لا نخترع اختصاصًا طبيًا للكوتش أو نضيف وعود علاج/خسارة وزن عامة. نتائج العملاء تبقى خاصة بالصور المعتمدة.

### R12 — توحيد هوية الكوتش ودلائل الخبرة

- [ ] مراجعة الاسم العربي والإنجليزي والنبذة والشهادات المعروضة والحسابات الرسمية وارتباطها المتبادل بالموقع؛ مراجعة هل صفحات «عن الكابتن» والتواصل تقدم إجابة كافية عن صاحب الخدمة.
- معيار الإغلاق: هوية واحدة متسقة ومعرّفات بيانات منظمة ثابتة، روابط حسابات صحيحة، وشهادات معروضة بأسمائها وتواريخها الحقيقية؛ لا أسماء عملاء أو معلومات خاصة جديدة.
- تحديث الحسابات الخارجية يتم مع المالك. النطاق الخاص تحسين اختياري للهوية والاستقرار، وليس شرط فهرسة أو سببًا مثبتًا للمشكلة؛ لا شراء أو نقل نطاق دون طلب.

### R13 — روابط وإشارات خارجية حقيقية

- [ ] جرد الروابط الحالية أولًا، ثم تحديد فرص مهنية مناسبة: تعريف صحيح في ملفات الكوتش العامة، تعاون موثق، أو محتوى تحريري مفيد يربط بالموقع.
- معيار الإغلاق للجرد: مصادر الروابط الحالية وفرص مناسبة موثقة. أي نتيجة تواصل أو نشر تسجل كما حدثت، ولا يُعلّم البند مكتملًا لمجرد كتابة قائمة فرص.
- لا روابط مشتراة أو تقييمات/شهادات مزيفة. لا رسائل لأشخاص أو نشر خارجي دون تعليمات صريحة من المالك.

## المرحلة الرابعة — GEO قابل للاختبار

### R14 — تدقيق وصول محركات الإجابات

- [ ] مراجعة تعليمات روبوتات البحث ذات الصلة من وثائق مزوديها وقت التنفيذ، ثم مقارنة robots وقيود CDN/WAF والاستجابات وأي سجلات متاحة.
- معيار الإغلاق: إمكانية الوصول إلى الصفحات المهمة موثقة لكل مزود بحدود الدليل المتاح. اختبارات user-agent لا تسمى زيارات بوت موثقة؛ غياب سجلات متاحة يظل مذكورًا.
- في OpenAI، OAI-SearchBot للبحث وGPTBot للتدريب؛ السماح بالتدريب ليس شرط ظهور البحث. لا نغير تفضيلات تدريب النماذج لأجل افتراض تحسن الترتيب.

### R15 — صياغة يسهل فهمها والاستشهاد بها

- [ ] تدقيق وجود إجابات نصية واضحة: من الكوتش، لمن الخدمة، أين تقدم، ماذا تشمل، الأسعار الفعلية، الفرق بين الباقات وطريقة الاشتراك. تحسين الفقرات الغامضة في نفس الصفحات قبل إضافة صفحات جديدة.
- معيار الإغلاق: الإجابات متاحة في HTML ومترابطة، والبيانات المنظمة تطابق النص الظاهر، وأي رقم تجاري يأتي من المصدر المشترك. المعلومة المهمة ليست محصورة في بوستر.
- لا «ملف سحري» أو schema خاصة تضمن GEO. Google لا يطلب ملفات AI نصية إضافية للظهور في AI Overviews/AI Mode؛ هذا لا يمثل حكمًا على كل مزود آخر. llms.txt تجربة اختيارية منخفضة الأولوية إن ظهر استخدام موثق، وليس بند إطلاق إلزاميًا.

### R16 — اختبار ترشيح مستقل لكل منصة

- [ ] اختبار ChatGPT وGemini وClaude مع تفعيل البحث عندما يتاح، بأسئلة عامة ثم أسئلة بالاسم منفصلة، دون إعطاء رابط الموقع في اختبار الاكتشاف العام.
- عينة عامة: «ابحث على الويب ورشح لي ٣ مواقع لمدربين لياقة بدنية أونلاين في مصر بيقدموا خطة تمرين وتغذية شخصية، وحط رابط كل موقع رسمي». وعينات للأسعار والمبتدئين تختار بعد R10.
- معيار إنجاز الاختبار: المنتج/النموذج/حالة بحث الويب/السؤال/اللغة/التاريخ/وجود محادثة سابقة/الروابط المستشهد بها موثقة؛ نسجل عدم الظهور أيضًا. إذا تعذر وصول منصة نسجلها «لم تختبر».
- نفرق بين ذكر الاسم، ورابط مصدر، وترشيح فعلي، وصحة المعلومات. الاسترجاع بالاسم ليس نجاح ترشيح عام. نكرر عينة ثابتة عبر الوقت؛ ترتيب إجابة واحدة ليس ترتيبًا دائمًا. Google AI Mode وGemini تطبيقان مختلفان في القياس.

## المرحلة الخامسة — قياس واستمرار الجاهزية

### R17 — سجل أداء واضح ومتابعة أسبوعية

- [ ] تسجيل خط أساس من Search Console وBing عند توافر البيانات، ثم مقارنة فترات متساوية، مع فصل مصر/العربية والاسم/الخدمة والصفحات.
- معيار الإغلاق التشغيلي: الظهور والنقرات وCTR ومتوسط الترتيب ومصدر/فترة كل رقم موثقة، إلى جانب سجل عينات GEO. لا نحسب نسبة «توصية» دون عدد عينات وتعريف واضح.
- قياس ضغطات واتساب/إنستاباي اختياري، ويُصمم دون جمع بيانات صحة أو هوية عميل ودون اعتباره دليل دفع. لا نضيف أدوات تتبع لمجرد استكمال قائمة SEO.
- هذه متابعة متجددة وليست مهمة تنتهي بعد أسبوع واحد. لا توجد أتمتة أو مواعيد تذكير منشأة بهذه الخطة.

### R18 — بوابة قبول قبل كل نشر مهم

- [ ] التأكد من مرور lint وtypecheck والاختبارات المناسبة والبناء مع SITE_URL الصحيح؛ فحص مباشر للنسخة المنشورة بعد الإصدار، وتسجيل أي قيد غير محلول مع مسؤول وخطوة تالية.
- [ ] إضافة فحوص SEO مركزة للمشاكل ذات الأثر عند التنفيذ: ناتج metadata وsitemap لكل لغة والمسارات المهمة وعدم وجود noindex غير مقصود. لا نضيف اختبارات تكرر النصوص بلا قيمة.
- معيار الإغلاق: أدلة إصدار محددة ونسخة يمكن الرجوع لها، وعدم نشر private/ أو originals أو لقطات غير مطموسة. robots ليست وسيلة لحماية ملفات خاصة.

## متى نسمي الموقع عالي الجاهزية؟

**جاهزية التنفيذ التي نتحكم فيها:** نشر النسخة المتفق عليها، وعدم وجود عائق تقني حرج معروف، وإتمام مراجعة المسارات والمحتوى والهوية والوصول مع أدلة الاختبارات وتوثيق القيود، وتجهيز القياس. تعطل مزود خارجي لا يُخفى ولا يُحسب نجاحًا.

**نتائج الاكتشاف الخارجية:** نجاح قراءة الخريطة وفهرسة الصفحات المهمة وبدء بيانات الظهور. كل نتيجة تُسجّل مستقلة؛ لا نجعلها وعدًا بتاريخ ثابت.
